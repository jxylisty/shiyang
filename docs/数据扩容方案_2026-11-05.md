# 数据扩容方案（2026-11-05）

> 阶段目标：把 `shiyang.db` 的药材/成分/靶点数据从「73 方涉及的 34 味药」扩到「药食同源目录 106 味全覆盖」，
> 并为每味新药材挂上成分与成分-靶点关联。所有数据可溯源（HERB ID / SymMap / PubChem），不编造。
>
> 本方案基于 research-scout 2026-11-05 调研（docs/自定义茶罐_数据来源调研.md）+ 本日复测。

## 0. 复测结论（修正调研文档的两处偏差）

1. **HERB `detail_api` 的返回结构**：数据在**响应顶层**（`herb_ingredient` / `herb_target` / `summary` / ...），
   不是调研文档写的 `res_data` 里。`search_api` 才在 `res_data`。已实测金银花 386 成分/118 靶点、决明子 184/39、荷叶 130/217。
2. **`search_api` 精确命中口径**：候选行第 3 列（中文名）== 输入词。74 味待新增药材直查命中 62；其余 12 味用异名表
   （大枣/生姜/芥子/紫苏子/胡椒/白茅根/芦根/广藿香/玳玳花/扁豆花/槐花/龙眼肉等）解决。**实测全 74 味可命中或用正名映射**。

## 1. 范围与口径

| 项 | 现状（2026-11-05 实测） | 目标 |
|---|---|---|
| herb | 34 味（全部 is_food_homology=1） | **106 味**（data/food_homology_catalog.json 全目录） |
| rel_herb_compound（v1/v2/v3） | 201 / 63 / 63 条 | 新药材按 HERB `herb_ingredient` 灌入 |
| compound | 165 个（带 SMILES/prob_cctcm/radar） | 新增成分带 SMILES（HERB summary `Molecule smile` 字段），**预测列留 NULL** |
| rel_compound_target | 12,168 条（带 source_db/activity） | 新增成分带 `ingredient_target`（来源标 herb.ac.cn） |
| 中文性味归经 | SymMap 覆盖（herb_service 已接） | 新药材自动被 SymMap dict 覆盖（本地 xlsx 703 味） |

**红线**：
- 新成分的 `prob_cctcm` / `radar_*` / `ad_level` 等模型预测列**一律 NULL**，不得给新成分跑模型伪装成本地口径。
- 新靶点 `target.species` 未知时写 `'未知(herb.ac.cn)'`，不得冒充实测物种。
- 每味药材 `functions` 存 HERB 英文 Function 原文，`source`/`reference_url` 记录 HERB ID 与详情页 URL。
- 灌库脚本可重复执行（幂等：按 herb.name / compound.id upsert，不重复插关联）。
- 灌库前备份 `data/shiyang.db`；运行时连接保持 `mode=ro` 不变，灌库只在 scripts 离线做。

## 2. schema 变更（最小增量）

- `herb` 加列：`source TEXT`（如 `herb.ac.cn HERB003070`）、`reference_url TEXT`、`added_batch INTEGER`（20261105）
- `compound` 不加列：现有列已够（id 用 HERB 的 HBIN ID，name/SMILES/mw 可填）。
  **注意**：新成分没有本地 `compound_map`/`recipe_analysis` 记录，凡 JOIN 这些表的功能要能容忍缺失（D4 核查项）。
- 关联表：新药材成分关联写 `rel_herb_compound`（v1，与 build_db.py 惯例一致），`rel_herb_compound_v2/v3` 不动
  （它们是「归属重建」的 asthma 口径专用）。

## 3. 分工

| 交付物 | 负责 | 验收 |
|---|---|---|
| D2 schema 迁移 + 备份方案 | db-architect | 迁移函数幂等可重跑；旧数据 0 丢失（行数前后对比） |
| D3 灌库脚本 `scripts/import_herbs_20261105.py` | backend-engineer | 106 味全入库、异名映射表落盘、每味带 source；重复执行第二遍 0 变更 |
| D4 成分/关联灌库 + 产品层 NULL 容忍核查 | backend-engineer | 新成分带 SMILES 入库；自定义鉴方/成分词典页对新数据不报错 |
| D5 一致性校验 + 自检 + 文档 | team-lead 汇总 | check_consistency 通过、pytest 通过、docs 更新 |

## 4. 不做什么（本阶段边界）

- 不给新成分跑 PU-Learning/UMAP/radar 预测（模型输入域外，跑了就是编造）。
- 不动 `rel_herb_compound_v2/v3`、`recipe_analysis`、`recipe_pathway`（它们只服务 73 方既有口径）。
- 不抓 dayi.org.cn（版权边界，调研文档已定调人工校准）。
- 不做前端新功能（数据层阶段；前端兼容性只做回归核查）。
