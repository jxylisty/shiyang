# 自定义茶罐 · 功能设计方案

> v0.1 草案 · 2026-11-05
> 基于 HERB 数据库可用的前提（见 `自定义茶罐_数据来源调研.md`），不做纯 AI 瞎编路线

---

## 一、这个功能解决什么问题

用户在小红书 / 公众号 / 朋友那里看到一个养生茶方（"决明子 + 菊花 + 枸杞，护肝明目"），心里打问号：
- 这几味东西放一起，真的有网上说的效果吗？
- 每味到底管什么的？是真有依据还是养生博主瞎凑的？
- 为什么有效？（不要说术语，说人话）

**用户不是来"配茶"的，是来"鉴茶"的。** 这是和现有茶罐（反向配伍：我有这些食材能煮什么方）本质的区别。

---

## 二、入口和定位

**不单独开新页面**，放在现有「我的茶罐」页里，加一个 tab 切换：
- tab 1：**我的茶罐**（现有功能不变）—— 勾选手边有的食材，看能煮哪些收录方
- tab 2：**自定义鉴方**（新功能）—— 输入一个从别处看到的方子，看看靠不靠谱

理由：
1. 两个功能的心智模型很接近（"输入一组食材 → 得到分析"），放在一起用户不用学新入口
2. 避免导航栏再加一个图标（已经 6 个了，再加就挤了）
3. 可以共享食材搜索、图片、布局等组件

首屏 tab 1 保持不变（老用户不被打扰），tab 2 用一个「新」角标吸引尝试。

---

## 三、用户路径（MVP）

```
用户粘贴/输入方子 → 解析出几味药材+克重 → 一键分析 → 结果页
```

### 3.1 输入形式（MVP 只做 1，其余后补）

**MVP：文本粘贴 + 逐味手动添加**

输入区分两块：
1. **粘贴整段文案**：一个文本框，用户把小红书/公众号里的方子描述粘贴进去。AI 负责从里面提取出「药材名 + 克重」的结构化列表。
   - 为什么要 AI：自然语言提取比正则靠谱，比如"金银花 3 克、菊花 5 朵、枸杞一小把"这种不规范表述也能处理
   - 为什么要粘贴：用户的真实场景就是从别处复制过来的，不是从列表里勾
2. **手动逐味添加**：一个输入框 + "添加"按钮，用户也可以一味一味手动加/改克重
   - 作为 AI 提取失败时的兜底
   - 也方便调整

解析后展示为可编辑的芯片列表（类似现有茶罐的"已选"区，但带克重输入框），用户可以增删改，确认后点「分析这个方子」。

**P2 加**：拍照识别（OCR + AI 提取）
**P3 加**：分享链接直接导入（从微信/小红书分享链接导入）

## 四、结果页结构（核心设计）

### 设计原则

- **药材层说人话，成分层做证据**——导师要求"在药材食材层就能讲清楚效果，所含成分作为辅助"
- **不说"有效/无效"这种绝对话**，说"有 X 味药材的传统功效支持这个说法 / 有 Y 个成分的体外实验数据 / 目前没有直接临床证据"
- **每个结论都要能追溯**——数据来自 HERB / 本地库 / 文献，标清楚来源层级

### 结果页分 5 块

#### 第 1 块：一句话结论（最顶部，大字）

不是"有效"或"无效"，是**一句话定性 + 证据等级**。

模板（示意）：
> **这个方子的 4 味药材里，有 3 味的传统功效与「清肝明目」的说法吻合。**
> 目前找到 12 个相关成分的体外活性数据，但**尚无直接临床实验证据**。
> 证据等级：B（实验数据 + 传统应用）

证据等级沿用现有 `evidence_service.py` 的 A/B/C 三级，但重新解释：
- **A**：有随机对照试验或临床实验支持
- **B**：有体外/动物实验数据 + 传统功效记载吻合
- **C**：只有传统功效记载，无实验数据

#### 第 2 块：逐味药材说人话（药材层 · 主视觉）

每味药材一张卡片，说清楚：
- **这味药是干嘛的**（1-2 句白话，比如"菊花：常用于缓解眼睛干涩和头胀"）
- **性味归经**（小字辅助，给懂的人看）
- **传统功效**（HERB/dayi 的中文功效描述，做简短化处理）
- **主要活性成分 Top 3**（成分名 + 入血概率，小字，作为"为什么有效"的支撑）
- **数据来源**：HERB / 本地收录 / 药典

这一块是结果页的主体，占最大面积。用户看完这一块就基本明白了，不用往下翻。

#### 第 3 块：成分 & 靶点（成分层 · 折叠展开）

默认折叠，标题写"查看成分机理（共 X 个成分 / Y 个靶点）"。
展开后展示：
- 高频成分 Top 10 列表（成分名 + 多少味药里有 + 入血概率均值）
- 高频靶点 Top 10 列表
- 一个简化的网络图（可复用现有 NetworkGraph 组件，数据量大会卡就降采样）

这一块是"辅助"，用户想看再看，不抢主视觉。

#### 第 4 块：参考文献 & 出处（证据层）

- 有多少篇文献支持（数量）
- Top 3 文献（标题 + 期刊/年份 + 实验类型：临床/动物/体外）
- "数据来源：HERB 数据库（herb.ac.cn）+ 本地成分库"
- 免责声明（成分活性为体外实验结果，不等同于体内功效）

#### 第 5 块：相似收录方推荐（转化出口）

"如果你喜欢这个方子，也可以试试我们收录的这些方——成分和功效类似，但出处更明确"

列出 2-3 个本地收录方（按成分重叠度排序），直接跳转到方子详情页。

目的：把用户从"鉴方"引导到"收录方"，增加平台自有内容的曝光。

## 五、与现有方子详情页的关系

**方向：已有收录方的详情页，按"药材层说人话"的思路优化上半部分。**

具体改动方向（P2 做，这次先记下来）：
1. 方子头部下面加一段"人话版一句话总结"（1-2 句，说清楚这个方子是干嘛的、适合什么人）
2. 配料列表里每味药加 1 句话功效提示（hover 或展开）
3. 成分说明书保留，但位置放到"药材功效"之后，作为"为什么有效"的支撑
4. 已有的证据链 / 网络图 / 暴露量 全部保留，位置后移

逻辑和自定义茶罐的结果页一致：**先讲人话，再给证据**。

## 六、MVP / P2 / P3 分期

### MVP（第一版，能跑通核心路径）
- 「我的茶罐」加 tab 2：自定义鉴方
- 文本粘贴 → AI 提取药材+克重 → 可编辑 → 分析
- HERB API 封装 + 缓存（后端）
- 结果页：一句话结论 + 逐味药材白话 + 成分/靶点折叠 + 参考文献 + 相似方推荐
- 证据等级标注（A/B/C）
- 免责声明到位

### P2（体验增强）
- 已有收录方详情页按"药材层说人话"优化
- 成分网络图（降采样版）
- 自定义茶方可以保存到"我的收藏"（带标记：自定义）
- 分享功能（生成分享图/链接）

### P3（高级功能）
- 拍照识别方子（OCR + AI）
- 两个方子对比（"这两个方子哪个更适合我"）
- 体质适配分析（结合用户体质档案，说"对你来说这个方子合不合适"）
- 营养成分分析（USDA 数据，食材层面）

---

## 七、关键约束（必须遵守）

1. **不编造**：AI 只能做翻译和结构化解说，不能编造功效或数据。所有功效/成分/靶点必须来自 HERB 或本地库
2. **不绝对化**：不说"有效""无效"，说"有 X 项证据支持""尚无临床证据"
3. **证据分级**：每个结论标清楚来源层级（A 临床 / B 实验 / C 传统）
4. **免责声明**：结果页必须有场景化免责，不只是页脚那条
5. **缓存策略**：HERB 数据必须缓存，不能每次分析都打网络请求
6. **失败兜底**：HERB 查不到的药材，明确标"未找到相关数据"，不硬凑

---

## 八、待确认问题（需要后端技术方案出来后定）

1. **缓存存在哪**：SQLite 表？还是文件缓存？（建议 SQLite，可复用现有数据库结构）
2. **成分合并逻辑**：多味药有相同成分时，怎么合并展示？（只去重计数？还是加权？）
3. **克重怎么用**：HERB 没有含量数据，用户输入的克重能用到什么程度？（目前看只能作为"这味药在方子里占比"的参考，不能算剂量）
4. **AI 解析药材名的准确率**：DeepSeek 能不能稳定地从中文自然语言里提取出规范药材名 + 克重？

---

## 九、和现有茶罐的关系总结

| 维度 | 我的茶罐（现有） | 自定义鉴方（新增） |
|---|---|---|
| 输入 | 从食材池勾选 | 粘贴文案 / 手动输入任意药材 |
| 数据源 | 本地 39 种食材 | HERB + 本地（更广） |
| 输出 | 能煮哪些收录方 | 这个方子靠谱吗 / 为什么 |
| 核心动作 | 反向配伍（找匹配） | 功效鉴定（给判断） |
| 结果重心 | 方子列表 | 药材功效解读 + 证据 |

两个功能互补，不替代。
