# 功能扩展调研清单（2026-10）

> 目的：为「食养有据」构思扩展功能 → 对照 GitHub/Gitee 开源项目与市面成品排查撞车 → 留下有价值的方向。
> 调研渠道：GitHub Search API（药食同源/食疗/体质/网络药理学/知识图谱/舌诊等 10+ 组关键词）、Gitee API、搜狗/必应网页搜索、小米应用商店与豌豆荚抽查、竞品仓库源码抽样阅读。
> 说明：Gitee 中文搜索页为 JS 渲染无法直接抓取，但其开源项目与 GitHub 高度重叠，已通过 GitHub 中文仓库交叉覆盖。

## 一、竞品调研结论（撞车总览）

### 开源项目

| 项目 | 相似度 | 情况 |
|---|---|---|
| donk05/herb-formula（5★，Streamlit） | ★★★ 最接近 | 同样做「药食同源 + 中药→化合物→靶点→疾病」网络药理学推荐，还带 RAG 古籍问答和 Gemini 对话。但是单页研究演示：无用户系统、无体质测试闭环、无移动端、无打卡/收藏、无暴露量估计。**核心威胁，需持续关注** |
| jaynewchen/TeaRecommendSystem（0★） | ★★ | 「本草轻养茶饮推荐，基于中医经典理论」，桌面 exe，只有推荐没有证据链 |
| tyler-fire/tea-app（0★） | ★ | 150 茶方 + 87 食材的科普 App，静态内容 |
| 各类食疗小程序（安心食疗/食疗坊/DietRegimen 等，0-2★） | ★ | 课程设计级：菜谱列表 + 简单推荐 |
| 中医药知识图谱问答（ChineseMedicalQA 199★、泽兰抄 101★ 等） | ★ | 面向科研/demo 的图谱问答，不做用户级食养产品 |
| 网络药理学工具（TCMNP 68★、TianweiShen 34★、一键网络药理学 4★） | ★ | 给研究者写论文用的分析流水线，不是给用户的产品 |
| 舌诊开源（TongueDiagnosis 134★ + 一批 0★） | — | 拍照辨体质赛道拥挤，且医疗属性风险高 |
| 《本草拾珍》药材可视化（2★）、Toobey 本草电子书（2★） | ★ | 药材性味归经/配伍禁忌科普展示 |

### 市面成品

| 产品 | 情况 |
|---|---|
| 中国药食同源网 App、药食同源生活馆 | 行业资讯 + 商城导购，无体质测试、无成分证据 |
| 大家中医 | 面向中医师的工具（经方/开方），不是面向大众食疗 |
| 薄荷健康 / Keep 饮食 | 西方营养学视角（热量/宏量营养素），无活性成分/靶点概念 |
| 下厨房 / 豆果美食 | 菜谱社区，无任何成分科学层 |
| 问止中医、小鹿中医等 | 在线问诊，医疗资质门槛高，赛道不同 |
| 滋补品牌小程序（小仙炖等） | 卖货导向，无科学解释 |

**总结论**：核心定位「每个方子一张成分级证据链说明书（活性成分 → 入血概率 → 靶点 → 通路 → 文献）」在开源界和市面成品中**均无用户级产品**，护城河成立。唯一近似竞品 donk05/herb-formula 停留在研究演示阶段。**扩展方向应继续加深「有据」，而不是做泛泛的养生功能。**

## 二、扩展功能清单（撞车对照后分档）

### 第一梯队：加深护城河，几乎无撞车 ✅ 强烈推荐

| # | 功能 | 一句话说明 | 撞车情况 | 成本 |
|---|---|---|---|---|
| 1 | **方子对比实验室** | 两个方子并排对比：成分覆盖、入血化合物重叠度、靶点/通路差异、适合体质对照 | 无竞品做（网络药理学工具只面向单方分析） | 中：复用现有 network/exposure 接口 |
| 2 | **手边食材反向配伍**（"我的茶罐"） | 勾选手头有的食材 → 反向生成可行方子并附证据链，缺哪味提示可购 | herb-formula 是"疾病→配方"正向；反向"有什么→煮什么"无人做 | 中 |
| 3 | **证据分级与溯源页** | 每条功效标注证据级别（临床/动物/体外/数据库预测）+ 一键跳文献 | 无竞品做证据分级 | 低：数据侧补标注 |
| 4 | **入血概率可解释页** | 展示模型为什么判它入血概率高（分子量/极性/OB/Lipinski 特征贡献），科普化 | 完全无撞车，且直接展示课题 PU-Learning 亮点 | 中 |
| 5 | **慢病安全滤镜** | 糖尿病/高血压/孕期/哺乳期/儿童模式下自动过滤或警示禁忌方子与食材 | 小项目有"药膳禁忌"静态列表；结合成分库动态过滤是差异点 | 低-中 |
| 6 | **开放 API + 公开数据集** | 把 106 目录×成分×靶点数据以 API/数据集形式开放，供科研合作 | 无撞车；挑战杯/大创材料加分项，学术影响力 | 低 |

### 第二梯队：用户留存与传播，轻撞车 ✅ 推荐

| # | 功能 | 一句话说明 | 撞车情况 | 成本 |
|---|---|---|---|---|
| 7 | **21 天食养周期报告** | 已有打卡数据升级：周期性生成"你喝了什么、覆盖了哪些成分/靶点"报告 + 体质复测变化曲线 | 薄荷健康有记录报告但无食养视角；体质变化曲线无人做 | 低：数据已有 |
| 8 | **家庭体质档案** | 一账号给父母/孩子代测体质、分别推荐 | 问诊类有家庭档案，但食疗场景轻撞车 | 低-中 |
| 9 | **节气/季节推荐日历** | 二十四节气 + 换季场景推送当令方子 | 养生小程序普遍有（撞车中等），做轻量版即可，别投入过重 | 低 |
| 10 | **体质名片分享海报** | 现有方子海报扩展成"我的体质+本周食养"社交名片 | 撞车低，传播利器 | 低：复用 SharePoster |

### 第三梯队：谨慎 ⚠️（撞车高或有风险，需差异化设计）

| # | 功能 | 风险与建议 |
|---|---|---|
| 11 | AI 对话食养助手 | herb-formula 已有 Gemini+RAG 古籍问答（撞车高）；且大模型幻觉与"有据"定位冲突。若做必须：RAG 限定在自家方子库 + 回答强制引用成分/文献编号 |
| 12 | 拍照舌诊/识药材辅助判体质 | 开源一堆（最高 134★）+ 医疗风险高 + 与"成分证据"主线无关，不建议做 |
| 13 | 可穿戴数据接入（手环睡眠→安神茶饮） | 撞车低但工程重、依赖第三方，上线运营期再考虑 |
| 14 | 中英双语成分说明书 | 无撞车，留学生/国际传播有价值，但翻译工作量大，演示/比赛前再做 |

### 不做 ❌

- **电商/商城**：市面成品全是这个方向（药食同源生活馆等），撞车最严重且偏离课题定位
- **在线问诊/开方**：医疗资质门槛，红线风险
- **通用菜谱社区**：下厨房/豆果垄断，无差异化

## 三、一句话优先级建议

先做 1（方子对比）+ 5（慢病滤镜）+ 7（周期报告）——三者都直接复用现有数据与接口、无撞车、分别强化"专业感/安全感/留存"三个维度；6（开放数据集）随手可做、比赛材料直接受益；2（反向配伍）作为下一个小亮点迭代。
