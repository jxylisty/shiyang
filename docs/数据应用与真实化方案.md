# 数据落地应用与证据链真实化方案

> 三问三答：公开数据怎么用进产品？已核实论文怎么让证据链更"真实"？能借鉴出什么新功能？
> 基于 2026-10-26 对 `shiyang.db` 实际数据的核查（全文所有"现状"均经 SQL 实测，见附录），与《支撑论文清单.md》《竞品对比分析.md》《开源资源清单.md》三份调研文档配套使用。

---

## 总览：一页结论

| 问题 | 一句话答案 |
|---|---|
| 数据怎么应用 | 分四层落库：补含量区间、补靶点证据等级、ADME 双通道校验入血概率、PK 文献锚点；现有 3,970 条含量数据已能跑通"方子→克重→含量→入血"全链（实测 124/165 成分可关联） |
| 链如何更真实 | 把"预测值"升级为"预测值 + 独立工具交叉验证 + 文献实测锚点 + 不确定性分级"四件套，并诚实展示一致/分歧 |
| 借鉴什么新功能 | 5 个候选：证据等级分层、成分对比卡片、配伍禁忌预警、翻案机制（负空间页）、证据链时间线/贡献度 |

## 一、数据方面：怎么应用进产品

### 现状底子（SQL 实测，2026-10-26）

- `compound` 165 个**全带 SMILES**、全带 `prob_cctcm` 入血概率——可批量送任何结构预测工具
- `rel_compound_target` 12,168 条，**全部带 `source_db`**（KEGG 2501 / CTD 2444 / BindingDB 2419 / DrugBank 2406 / PubChem 2398）与 `activity_type`（IC50/表达调控/GI50 等）、`activity_value`——证据等级分层的原料已在库里
- `herb_compound_content` 3,970 条**数值型含量区间**（`content_min/max_pct`），其中 124 个成分能对上 `compound` 主表
- 73 方中 **55 方配料已填克重**——暴露量估计链路完整
- 全链贯通实测：recipe→material→content→compound→prob 五表 JOIN 一气呵成（示例：清咽利喉饮的绿原酸 = 金银花 0.81~4.6% × 菊花 0.14~0.73%）

### 应用一：把"暴露量×入血概率"合并成一条链（P0，改动最小、卖点最大）

当前 `exposure_service.py` 算完 mg 就停了，`prob_cctcm` 躺在另一张表里。合并后每个成分得到：

```
估计吸收暴露量 = 克重(g) × 含量(%) × 转移率(0.5) × 入血概率(prob_cctcm)
```

- 输出区间 `[min, max]` 保留，用户第一次能看到"这个方子里，我大概能吸收多少 mg 活性成分"
- 这条公式 = EFSA 暴露框架（论文清单#18）× PU-Learning 预测（#10）× 血清药物化学"入血才起效"（#11#12），答辩时三篇文献一句话串起来
- 需要同时做**克重补录**（73 方差 18 方）和**成分对齐**（content 表 41 个成分名与 compound 表对不上，如"1, 2-O-二-芥子酰基-β-D-吡喃葡萄糖苷"这类长名，用 PubChemPy 按名称/SMILES 归一化，或人工映射表）

### 应用二：target 表按物种/证据类型过滤（P0，纯查询改进）

现 target 表 2,807 个里只有 1,144 个人类蛋白（Danio rerio 579 / 大鼠 361 / 小鼠 346）。`recipe_analysis` 预生成时已按"Homo sapiens Protein"过滤，但**前端展示层应同样只呈现人类靶点**，并在页面注明"仅展示人类蛋白靶点（N 项）"。这是审稿人/老师一眼会挑的硬伤，改一行 WHERE 就补上。

### 应用三：ADME 双通道交叉验证（P1，让预测"可信"的关键）

165 个 SMILES 全量送 ADMETlab 2.0（网页批量提交，含 HIA 人肠吸收、F20%/F30% 口服生物利用度端点）和 pkCSM（intestinal absorption）：

- `compound` 表加列 `hia_admetlab`、`ob_f20_admetlab`、`caco2_pkcsm`、`admet_check_date`
- 产品展示层把"入血概率"升级为**双通道徽章**：自研 PU-Learning 预测 + ADMETlab/pkCSM 独立工具校验，一致✅、分歧⚠️（如实展示）
- 对外口径从"我们模型预测入血"变成"自研模型与两个学界公认工具交叉验证"——这是"真实化"最省力的一招；竞品调研确认无任何产品做这一层
- 顺带补齐 41 个未命中成分：COCONUT/PubChem 按名称/SMILES 检索归属

### 应用四：文献 PK 实测锚点（P2，逐方逐步做）

从论文清单 #2（山楂）/ #3（金银花）这类单味药综述里，人工摘录代表性成分的**药代动力学实测参数**（Cmax、Tmax、AUC、口服生物利用度 F%），进 `compound` 新列 `pk_reference`：

- 展示层呈现"绿原酸：动物实测口服生物利用度约 X%（文献）｜本平台预测 0.77"
- 有实测锚点的成分打"文献实测"徽章，没锚点的保持"模型预测"徽章——诚实分级，可信度反而更高
- 来源就挂在旁边（PMID/DOI），点击直达文献——把竞品分析里的"溯源首创"差异点做实

### 应用五：含量区间的"采收/炮制"维度（P2，锦上添花）

`herb_compound_content.content_raw` 现在是"0.06~0.10%"这种字符串。可加 `content_condition` 列（产地/炮制/测定方法），标注"此区间来自文献 X 的测定条件"。让暴露量估计从"看起来像编的"变成"每一步都可回溯"。

## 二、论文如何让"链"更真实

核心思路：**论文不是用来装点参考文献列表的，而是给链条的每一环换上可点击的实证依据**。当前链是「成分→入血概率(预测)→靶点→通路→出处」，按论文逐环加固：

### 2.1 "入血"环节：从预测值到实证闭环（最重要的真实化）

当前最薄弱、也最容易被打假的一环是"入血概率"——PU-Learning 模型再准，对外也只是个数字。用两篇文献把它焊死：

- **理论依据**：血清药物化学（#11 王喜军 2015）——"口服中药有效成分须经吸收入血、以血中移行成分形式作用于靶点"是学界公认理论，你的"入血才值得看"筛选逻辑不是自己发明的
- **鉴定方法**：Chinmedomics（#12 Chin Med 2024）——血清移行成分 + 代谢组学是鉴定入血成分的标准方法学
- **落地动作**：对金银花等明星药材，把文献报道的血清移行成分（如绿原酸、木犀草素已确认入血）打"✅ 文献已确认入血"徽章——**预测对了的，用文献证明你对了**；这比任何 ROC 曲线都有说服力
- 展示话术："入血概率为 PU-Learning 模型预测（方法学先例 Sci Rep 2017），其中 X 个成分已被血清药物化学文献实测确认"

### 2.2 "成分→疾病/功效"环节：用综述文献替换硬关联

`rel_compound_target` 里 CTD 的 `increases^expression`、BindingDB 的 IC50 是**体外结合/表达数据，不等于体内功效**——这是评委最可能追问的点。加固方式：

- 对 top 靶点补 DisGeNET/GeneCards 的基因-疾病关联（"STAT3 与炎症性疾病的关联有 N 篇文献支持"），`source_db` 里已有 KEGG 通路注释
- 疾病机制综述（#2 山楂、#3 金银花、#4 抗炎成分）给出"成分→药理作用"的**文献级定性证据**：展示层每个成分挂"文献支持：Front Oncol 2024 报道木犀草素具抗炎活性"
- 诚实口径：体外靶点标"体外证据"，通路富集标"生物信息学推断"，文献综述标"文献证据"——三级分层，全行业（含 Examine.com）都这么做

### 2.3 "推荐与评价"环节：量表与暴露量的方法学背书

- 体质判定：CCMQ 简版信效度（#13）——测评不是星座表，是 21,948 例流调验证的量表
- 暴露量：EFSA 联合暴露指南（#18）——"剂量×含量"是欧洲食品安全局的规范操作，且 EFSA 明确要求呈现不确定性——顺势把区间/保守假设/敏感参数展示出来，规范反而成为卖点
- 网络药理学全流程：#6（李梢 AI 网络药理学）+ #7（Chin Med 2025 流程规范）——整个管线的方法学正统性

### 2.4 一张"证据等级"表（建议进详情页 + 答辩 PPT）

| 证据层 | 来源 | 可信度标签 | 示例 |
|---|---|---|---|
| L1 人体/动物实测 | PK 文献、血清药物化学 | ✅ 文献实测 | 绿原酸入血已实测 |
| L2 交叉验证预测 | ADMETlab/pkCSM + 自研模型 | 🔬 双通道一致 | F20% + prob 0.77 |
| L3 单模型预测 | PU-Learning | 📊 模型预测 | prob_cctcm 0.95 |
| L4 体外/生物信息 | CTD/BindingDB/KEGG/富集 | 🧪 体外证据 | IC50、GO 条目 |

用户看到的每个数字旁边都挂着等级标签——**"真实"的本质不是每个数字都实测，而是每个数字都声明了自己的证据等级**。这也是对竞品分析结论（无产品做到此层）的直接兑现。

## 三、借鉴思路：可开发的新功能

从 18 篇论文 + 14 个竞品里提炼，按"价值×工作量"排序：

### F1 · 成分对比卡片（借鉴 Examine.com，P1，前端为主）

Examine 用"成分页 + 证据分级"征服了营养领域。给库里明星成分（绿原酸、橙皮苷、金丝桃苷、甘草苷…）做独立"成分档案页"：来源药材、含量区间、入血概率双通道、三维雷达、top 靶点、支持文献。方子详情页里的成分名全部可点进入档案页——从"方子说明书"升级为"成分维基"，内容资产可积累、可被搜索（长尾 SEO），且与竞品"茶养"彻底拉开形态差距。

### F2 · 配伍禁忌与安全预警（借鉴 ShenNongDiet 的禁忌建模 + TCM-DS，P1）

ShenNongDiet 论文显式建模体质适宜性与配伍禁忌，而 `herb` 表已有 `toxicity/contraindication` 字段闲置。做法：方子详情页"安全性"卡片——食材级禁忌（孕妇/脾胃虚寒）+ 体质不适宜（`constitutions_unsuitable` 字段已有数据）+ 简单配伍规则。**先做"警示"后做"推荐"是合规安全区**（红线要求），也是家长/老师群体最买账的功能。

### F3 · 方子横向对比（本项目数据独有，P1.5，纯前端+预生成）

同场景下勾选 2-3 个方子，对比表：成分重合度、入血概率分布、三维雷达、暴露量区间、靶点交集韦恩图。现有 69 条 `recipe_analysis` 直接支撑，无需新数据——**竞品没有任何一家能做这个功能，因为他们没有分子层数据**。分享海报出"对比图"版本，传播性更强。

### F4 · "为什么没推荐"负空间页（借鉴推荐系统透明化，P2）

体质测评后，除了推荐方子，再展示"这些方子被排除了，因为：含你体质不宜的 X 材 / 入血成分不足"。信任来自可解释的排除，而不只是可解释的推荐。用户访谈里"相信这个结果吗"的疑虑直接被回应。

### F5 · 证据链时间线 + 争议区（借鉴 Examine/EFSA，P2）

每个成分页加"证据历史"：什么时间哪个库收录、哪篇文献支持/质疑。入门级做法是按 `admet_check_date` + 文献年份排序的时间线。传达"证据是活的、会更新"的科学观感，区别于所有静态养生 App。

### F6 · 中医大模型 AI 解读（借鉴 TCM-DS/仲景，P2.5，可选）

用户已可配 DeepSeek Key 体验 AI 解读。升级方向不是自训模型（成本高、无必要），而是**RAG 化**：用 Awesome-TCM-LLM 索引的语料 + 本库 3,970 条含量/12,168 条靶点关系做检索增强，让 AI 回答"这个方子的成分依据"时引用库内条目而非自由发挥。TCM-DS 用 426 种物质/288 方做到 0.99 精度的配置，证明这个数据量级够用。

### 不建议做的（避坑）

- ❌ 自训/微调中医药大模型——算力与语料成本不匹配大创预算，RAG 已够
- ❌ 把 `rel_herb_compound` 的成分归属直接展示——抽样报告已发现归属错乱（人参皂苷挂薄荷），需 TCMSP 重建后再上 F1 的"来源药材"字段
- ❌ 采集网页药膳数据扩充方子库——红线规定"网方不采信"，宁缺毋滥

## 四、落地路线（与 README 路线图对齐）

| 优先级 | 事项 | 动到哪 | 依赖 |
|---|---|---|---|
| P0（本周可做） | 暴露量×入血概率合并展示 | `exposure_service.py` 一处 JOIN | 补 18 方克重 |
| P0 | 靶点展示层只出人类蛋白 | 前端查询 WHERE + 页面注明 | 无 |
| P1 | ADME 双通道批测 + 徽章 | `compound` 加 4 列 + 展示层 | ADMETlab 网页批量提交 |
| P1 | 证据等级标签体系（L1-L4） | 展示层组件 + 数据加 `evidence_level` | PK 文献摘录（金银花先行） |
| P1 | 成分对比卡片 F1 + 禁忌预警 F2 | 新路由/新页 | `contraindication` 数据核对 |
| P1.5 | 方子横向对比 F3 | 预生成对比 JSON | 现有 69 方分析即可 |
| P2 | 文献 PK 锚点、负空间页 F4、时间线 F5 | 逐月迭代 | — |

**答辩叙事升级**：原来的故事是"我们做了体质→方子→成分链"；真实化之后的故事是"链上每个数字都有证据等级、每个等级都可溯源到工具或文献、每个工具都是学界公认的"——把《竞品对比分析.md》的 4 个差异点，从'功能差异'升维成'可信度体系差异'。
