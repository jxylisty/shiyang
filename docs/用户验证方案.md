# 用户验证方案（P1.4 · 答辩用）

> 目标：30 份校内试用 + SUS 可用性得分 + 3 例典型用户访谈，把"自嗨"变成"已验证"。
> 执行人：项目组成员；周期建议 2 周；本文件含可直接发放的问卷与访谈提纲。

## 一、试用流程（发给每位试用者）

1. 扫码/点链接打开「食养有据」（部署后为正式域名，试用期为局域网或内网穿透地址）
2. 注册账号（30 秒）
3. 完成 67 题体质测评 → 查看体质结果与推荐方子
4. 进入「护嗓润喉」专区任选 1 个方子，查看完整详情页：配方、成分说明书、三维评分、网络图、暴露量估计
5. 点「生成分享海报」保存一张图
6. 收藏 2-3 个方子，在「我的」页面查看档案与收藏
7. （可选）配置自己的 DeepSeek API Key 体验 AI 解读
8. 填写 SUS 问卷（约 3 分钟）

## 二、SUS 可用性问卷（System Usability Scale，10 题）

> 指导语：请根据刚才的使用体验，对每句话选择最符合您感受的分数（1=非常不同意，5=非常同意）。

| # | 题目 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 1 | 我认为我会经常使用这个系统 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 2 | 我觉得系统过于复杂 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 3 | 我认为系统很容易使用 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 4 | 我觉得需要专业人员的帮助才能使用这个系统 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 5 | 各项功能整合得很好 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 6 | 系统里有太多不一致的地方 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 7 | 我想大多数人很快就能学会使用这个系统 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 8 | 我觉得系统用起来很别扭 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 9 | 我对使用这个系统有信心 | ☐ | ☐ | ☐ | ☐ | ☐ |
| 10 | 在使用前我需要先学习很多东西才能上手 | ☐ | ☐ | ☐ | ☐ | ☐ |

**计分方法**：奇数题（1,3,5,7,9）得分 = 选项值 − 1；偶数题（2,4,6,8,10）得分 = 5 − 选项值；总分 × 2.5 = SUS 分（0-100）。
**判读**：68 分为及格线（行业平均）；>80 为优秀（A 级）。答辩汇报时报告：均值、标准差、分布图。

**补充题**（不计入 SUS，用于产品迭代）：
- NPS：您有多大可能把这个平台推荐给同学？（0-10 分）
- 您最常用的功能是？（体质测评 / 护嗓专区 / 成分说明书 / 网络图 / 暴露量 / AI 解读 / 收藏）
- 「成分说明书」对您理解"这杯茶凭什么有用"的帮助程度？（1-5）
- 您最希望增加什么功能？（开放题）

## 三、典型用户访谈提纲（3 例：1 医药背景 / 1 非医药背景 / 1 教师或嗓音从业者）

1. 请用一句话说说您理解的这个平台是做什么的。（检验价值传达）
2. 测评结果和您自我认知的体质一致吗？您相信这个结果吗？为什么？（检验可信度）
3. 看到"入血概率 0.97""三维评分"这些数字时，您的第一反应是什么？看得懂吗？（检验术语门槛）
4. 如果嗓子不舒服，您会真的照着方子泡一杯吗？会犹豫什么？（检验行为转化 + 顾虑）
5. 和您用过的其他养生 App/小程序比，这个最不一样的地方是什么？（检验差异化感知）
6. 什么情况下您会再打开它？什么情况会让您删掉它？（留存与流失点）

## 四、执行清单

- [ ] 部署到公网（Vercel+Render）或临时内网地址
- [ ] 问卷用问卷星/腾讯问卷建好（照抄第二节）
- [ ] 招募 ≥30 名试用者（班级群、社团群、教师办公室；记录专业背景比例）
- [ ] 完成 3 例访谈并整理逐字稿要点
- [ ] 统计 SUS 均值/标准差，制作分布图
- [ ] 汇总补充题高频需求，写入迭代计划（答辩可讲"用户驱动迭代"）

## 五、答辩话术参考

"我们在校内完成了 N=XX 的真实用户试用，SUS 可用性得分 XX.X（超过行业均值 68），其中『成分说明书』功能获得 X.X/5 的理解度评分；访谈中 XX% 的用户能准确复述平台的核心差异——成分证据链。"
